Reasoning models

From Lesson 5. Same loop, more generated tokens before the answer. You pay for all of them and see few of them.

The picture

input ──▶ [ thinking / reasoning tokens ] [ answer tokens ]
           output price, hidden/summary    output price, shown
           └──────── both inside max_tokens / max_output_tokens ────────┘

where it comes from:  post-training + RL on checkable answers (maths, code)
why it helps:         each token conditions on the steps already written

Terms

Reasoning modelA model post-trained (largely by RL) to generate a working-out before its answerR1
Thinking / reasoning tokensThe tokens of that working-out. Anthropic says "thinking", OpenAI says "reasoning". Billed as output.
Test-time computeSpending more computation at inference (more generated tokens) to improve an answer
Adaptive thinkingThe model decides per request whether and how much to think. Easy inputs may get no thinking block.A
EffortA soft control over how many tokens the model spends, thinking included. "A behavioral signal, not a strict token budget."A
Thinking summaryA readable summary of the reasoning, written by a different model. Never the raw chain of thought.A

Cost arithmetic

cost = input × in_price + (thinking + answer) × out_price
visible answer tokens ≈ output_tokens − thinking_tokens

docs example: 25 in, 348 out, 312 thinking → ~88% of the bill is thinking
(output is 5× input on current Claude models)

Consequences for builders

Set effort explicitlyDefaults differ by model, so an upgrade can silently change the bill
Size max_tokens for thinkingOtherwise you get stop_reason: max_tokens, maybe with no text, and you still pay
Estimate from usageCost per request is a distribution over inputs. Measure on real ones.
Tune per routeLow for chat and high-volume work, higher for multi-step reasoning. Confirm with evals.
display: omittedFaster first visible token. Same cost.
Summaries aren't audit trailsThey're written by another model, about reasoning that was trained for reward

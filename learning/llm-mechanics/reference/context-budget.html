Context budget

From Lesson 3. How much fits in one request, and how to tell when a reply was cut off.

The rule

input_tokens + max_tokens  ≤  context window    # input and output share one sequence
               max_tokens  ≤  max output        # per-reply ceiling, set by the model
input = system + messages + tools + images/docs    output = text + thinking + tool calls

Output counts because each generated token is appended and read on the next step (generation loop).Anthropic

Terms

Context windowAll tokens the model can reference while generating, including its own reply. Not the training data.
Max outputThe model's limit on tokens generated in one reply
max_tokensYour cap for this reply (OpenAI: max_output_tokens). A hard cut, not a length hint.
Stop reasonWhy generation ended. The only signal that a 200 OK reply is incomplete.
Context rotAccuracy and recall degrade as context grows. Fitting isn't the same as working.

What happens when it doesn't fit (Claude)

SituationResult
Finished on its ownstop_reason: "end_turn"
Hit your max_tokensstop_reason: "max_tokens"; truncated, every token billed
input + max_tokens > windowClaude 4.5+: accepted; may stop with "model_context_window_exceeded". Older: validation error.
input alone > windowHTTP 400, "prompt is too long". Nothing generated or dropped.
 Anthropic context-windows and stop-reason docs, read 2026-11-16. OpenAI: status: "incomplete", incomplete_details.reason: "max_output_tokens".

Rules of thumb

Words → tokensClaude's current tokenizer: 1M tokens ≈ 555K words ≈ 2.5M chars (≈1.8 tokens/word). Count real requests with count_tokens.
ThinkingCounts toward max_tokens and is billed as output. A tight cap can leave no visible text. OpenAI suggests reserving at least 25K tokens when you start out.
Large max_tokensClaude's Python SDK requires streaming above about 21K
Review checklistWhat bounds the input as data grows? Is the stop reason checked? How was max_tokens chosen?

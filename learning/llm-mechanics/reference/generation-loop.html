The generation loop

From Lesson 2. How a model turns a prompt into output, one token at a time.

The algorithm

tokens = tokenize(prompt)
repeat:
    logits = model(tokens)[-1]       # one score per vocabulary token
    probs  = softmax(logits)          # distribution over the vocabulary
    next   = choose(probs)            # greedy = argmax · sampling = lesson 7
    tokens.append(next)               # output becomes input
until next == end_of_text or len(new tokens) == max_tokens
return detokenize(new tokens)

P(w1:T | W0) = ∏t P(wt | w1:t−1, W0). Each token is conditioned on the prompt plus everything generated so far.HF

Terms

LogitsRaw scores, one per vocabulary token, from a single forward pass
SoftmaxTurns logits into a probability distribution over the vocabulary
Greedy decodingAlways take the argmax. Commits to near-ties, and can miss better sequences.HF
AutoregressiveEach output token is fed back in as input for the next step
End-of-text tokenA special token that ends generation (GPT-2: <|endoftext|>, ID 50256)
PrefillProcessing the prompt, all tokens in parallelNVIDIA
DecodeGenerating output, one token per forward pass; memory-boundNVIDIA
KV cacheStored attention keys and values for earlier tokens, so they aren't recomputed each step. Memory grows with sequence length.HF

Consequences for builders

LatencyMostly driven by output length, because decode is serial
Facts and numbersThe model produces the most plausible continuation, not a looked-up value. Put true values in the context.
SteeringChange the input, not the weights. Context changes the distribution but doesn't guarantee the answer.
No revisionOnce a token is emitted, every later token is conditioned on it
StoppingAlways set a max-token limit. HF generate() defaults to 20 new tokens.HF

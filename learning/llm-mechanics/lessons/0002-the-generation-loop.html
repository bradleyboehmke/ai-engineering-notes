The generation loop

Win: by the end you can explain next-token prediction as one softmax over the vocabulary, repeated in a loop, with each step conditioned on every token before it. You can also say what that means for latency and for wrong answers.

In lesson 1 you saw that a model reads token IDs. This lesson covers how it writes them. Everything later in the path depends on it: output limits, sampling, non-determinism, hallucination, and why output tokens are slow.

1. One step: a classifier over the vocabulary

Give the model a sequence of tokens and it returns one score (a logit) for every token in its vocabulary. Softmax turns those scores into a probability distribution over what comes next. Here is GPT-2, a small open model with a 50,257-token vocabulary, given The quarterly revenue increased by:

GPT-2 (124M), top 5 of 50,257 next-token probabilities. ␣ marks a leading space. Measured 2026-11-15 with experiments/step.py.

ML anchor This is a multiclass classifier with one class per token, so 50,257 classes for GPT-2 and about 200,000 for o200k_base. The features are the whole sequence so far. Pretraining fits it with cross-entropy on "what token came next" across a huge corpus. The part your ML intuition doesn't cover is what happens next: the prediction gets fed back in as an input.

2. The loop: pick, append, repeat

One step gives one token. To get text, you run the step in a loop:

tokens = tokenize(prompt)
repeat:
    probs = softmax(model(tokens))    # one forward pass, full vocabulary
    next  = choose(probs)             # greedy: argmax; or sample (lesson 7)
    tokens.append(next)               # the output becomes input
until next is the end-of-text token, or a max-token limit is hit

Hugging Face's generation guide puts it in one sentence: the model generates the next token given the prompt "along with its own generated outputs", until it reaches a set length or an end-of-sequence token.1 Formally, a sequence's probability factors into a product of next-token conditionals, P(w1:T | W0) = ∏t P(wt | w1:t−1, W0), where W0 is the prompt.2 Picking the argmax every time is called greedy decoding.

4. What the run shows

The number is made up. "$1.3 billion" is not in any source. Each digit was simply the most plausible token at that step. That matters for the analytics use case in your mission: a model asked for a figure always produces a plausible-looking one. Lesson 9 covers why.

A choice can't be taken back. Step 4 was close to a tie, and the model still committed to one token. From then on, "billion" and everything after it were conditioned on that one choice. Nothing in the loop goes back and revises earlier tokens.

Context shifts the distribution, but it doesn't do the calculation. I re-ran it with the facts in the prompt: Revenue was $40 million in Q1 and $46 million in Q2. From Q1 to Q2, quarterly revenue increased by $.

Where ML intuition misleads With a classical model, you change behaviour by retraining it. Here, the weights stay fixed and you change the behaviour by changing the input, because every token is conditioned on everything before it. That's why prompts, documents, and conversation history matter so much. The catch is in the table above: conditioning on the right facts makes the right answer more likely, but it doesn't guarantee it. GPT-2 is tiny, and larger models condition much better. The mechanism is the same.

5. Why a builder cares: input is parallel, output is serial

The loop explains a cost asymmetry you'll use in every estimate. The model processes the prompt in one parallel pass, called the prefill. It then generates output "autoregressively one at a time", which is the decode phase. Decode is memory-bound and leaves much of the GPU's compute unused.3 Inference servers keep a KV cache so each step doesn't recompute attention over the earlier tokens. The cache stores intermediate results for every token so far, so memory grows with the sequence.4

In practice, that means:

  • Latency mostly tracks output length. A 2,000-token prompt with a 50-token reply can return faster than a 200-token prompt with a 2,000-token reply. Lesson 15 adds the numbers (time to first token, tokens per second).
  • Output tokens use more hardware per token than input tokens. Keep that in mind when lesson 12 shows output priced above input.
  • The stop condition is part of the loop. Generation ends at an end-of-text token or a token limit. Hugging Face's generate() defaults to just 20 new tokens unless you set max_new_tokens.1 Lesson 3 covers the API version of this: max_tokens and the stop reason.

6. Check yourself

At one generation step, what does the model output?

One forward pass gives a score for every vocabulary token, and softmax turns the scores into a distribution. Choosing a token is a separate step: greedy decoding or sampling.

GPT-2 wrote "$1.3 billion". Where did 1.3 come from?

Each digit was the argmax at its step: '1' at 11.6%, then '3' at 10.5% in a near-tie. The model doesn't look up or compute a value. It continues the text plausibly.

Adding the Q1 and Q2 figures raised ' million' from 5.6% to 18.9%, but '6' barely moved. What does that show?

Every step is conditioned on the full context, so the context changed the probabilities. Here it helped with format and units but not with the arithmetic. The weights never changed.

Why does writing a 1,000-token reply take far longer than reading a 1,000-token prompt?

The prompt is processed in parallel (prefill). Output is generated one token per forward pass (decode), and each pass depends on the one before it.

From lesson 1: GPT-2's vocabulary is 50,257 tokens. During generation, that vocabulary is…

The vocabulary is the output space. The context window, not the vocabulary, limits how many tokens fit in a prompt (lesson 3).

Do this
  1. From learning/llm-mechanics/, add the model libraries to your venv (GPT-2 downloads on first run, about 500 MB): 
    .venv/bin/pip install torch transformers
  2. Run the script, which is already in experiments/step.py. Read it first. The loop is about ten lines. 
    .venv/bin/python experiments/step.py "The quarterly revenue increased by" 8
    Check that you get the same numbers as above. Greedy decoding on one machine should reproduce them. Lesson 8 shows where that stops being true.
  3. Before each run below, write down the top token you expect:
    • Change one early word (increased → decreased) and see which steps change.
    • Write a prompt where the answer is in the context, like the Q1/Q2 one, and check whether the model uses it.
    • Find a step where the top token has less than 15% probability. Those are the steps where sampling (lesson 7) will change the output most.

Leading this

Two habits come out of this lesson. First, when a design depends on the model producing a number or a fact, ask where the true value enters the context. If the answer is "the model knows it", that's a design risk, because the model returns the most plausible continuation, not a looked-up value. Second, when someone estimates latency, ask for the expected output length, not only the prompt size. Output is generated serially, so a verbose response format is a latency choice as well as a cost choice.

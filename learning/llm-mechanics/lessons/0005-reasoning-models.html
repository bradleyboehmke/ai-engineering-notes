Reasoning models

Win: by the end you can explain what thinking tokens are in terms of the generation loop, why you pay output prices for tokens you never see, and read a response's usage to say what share of the bill was thinking.

Lesson 4 showed that post-training changes behaviour: answering, stopping, tone. Reasoning models come from more post-training. The new behaviour is that the model writes a long working-out before it answers. Nothing about the loop changes. What changes is how many tokens a request generates, and who gets to read them.

1. Thinking is more of the same loop

Anthropic's docs put the problem plainly: "A model that answers in a single pass has to get everything right on the first try: no scratch work, no checking, no changing approach halfway through."1 A reasoning model gives itself that scratch work. Before the answer it generates thinking tokens (OpenAI calls them reasoning tokens), and the API returns them in a separate block or hides them.13

input ──▶ [ thinking tokens ………………………… ] [ answer tokens ]
           └─ generated by lesson 2's loop ──┴─ same loop ─┘
           billed as output                    billed as output
           hidden or summarized                shown to you

Why would writing more tokens give a better answer? Go back to lesson 2: each new token is predicted from everything before it. A model that writes "75% vs 80%, so B wins on desktop" has put that intermediate result into its own context, and every later token can build on it. More generated tokens means more computation spent on the answer. That's why this is also called test-time compute: spending at inference what you'd otherwise have to buy with a bigger model.5 Karpathy's version is that models "need tokens to think". A hard step squeezed into one token is likely to go wrong. The same step spread over several tokens has a better chance.6

2. Where the habit comes from: reinforcement learning

Lesson 4's post-training was imitation: SFT copies example replies, and preference tuning moves toward the replies people rated better. Reasoning models add a stage that pure imitation can't provide. You give the model problems with checkable answers (maths, code with tests), let it generate attempts, and reward the attempts whose final answer is correct. DeepSeek's R1 paper reports that reasoning ability can be built this way through "pure reinforcement learning", without "human-labeled reasoning trajectories", and that patterns like "self-reflection, verification" emerged on their own.4

ML anchor This is RL with a verifiable, outcome-only reward. Nobody grades the steps. The policy finds that longer chains with backtracking ("wait, let me recheck") score higher, so it learns to produce them. Two consequences follow from what you already know. First, the gains are largest where rewards were checkable, such as maths, code, and multi-step logic, and smaller on open-ended writing. Second, the reasoning text is a means to a reward, not a log written for you. Treat it the way you'd treat a model's intermediate activations: informative, but not a faithful explanation.

Where ML intuition misleads "Thinking off" isn't a stable property of a model. On current Claude models thinking is on by default, effort defaults differ by model, and with adaptive thinking the model decides per request whether to think. So the same code can produce very different output token counts on easy and hard inputs. Your cost per request is now a distribution, not a constant. Estimate it from measured usage on real inputs, not from the length of the answer you see.

4. Check yourself

Why are thinking tokens billed at the output price?

Thinking tokens come out of the same decode loop as the answer: one forward pass per token, which is the slow, memory-bound part of inference. Input is processed in parallel. That difference is why output costs more, and thinking is output.

A Claude response has an empty thinking block (display: "omitted"). output_tokens is 1,400 and thinking_tokens is 1,300. What are you billed for?

output_tokens is the inclusive billing total. Omitting the display saves latency, not money: "You're still charged for the full thinking tokens." Summaries, when you ask for them, aren't charged.

From lesson 3: a hard question with max_tokens=1000 comes back with stop_reason: "max_tokens" and no text block. What most likely happened?

Thinking and answer share one max_tokens budget, and thinking comes first. A prompt that's too long is a 400 error, not a stop reason. You paid for the input and the thinking and got no answer, which is why OpenAI advises reserving 25K tokens to start.

From lesson 4: where does the habit of long, self-checking reasoning mainly come from?

It's post-training again, but with RL and a checkable reward. DeepSeek reports that reflection and verification emerged without human-labeled reasoning trajectories. Providers do add a system prompt when thinking is on, but that turns the feature on. It isn't where the skill comes from.

With adaptive thinking at the default effort, you ask "What is the capital of France?" What should you expect?

Adaptive means the model decides on each request. At medium it "might skip thinking for simple queries". That's why code shouldn't assume every turn starts with a thinking block. The 1,024 minimum belongs to the legacy budget_tokens mode.

From lesson 2: why can writing out intermediate steps make an answer more accurate?

The weights don't change. The context does. Each intermediate result the model writes becomes input to every later prediction, so a hard step gets several forward passes instead of one.

A teammate says: "We set effort to low, the eval score held, so let's use low everywhere." What's the best reply?

The docs' own advice is to tune per workload and check with evals: low suits chat and high-volume routes, and the docs warn that lower effort can skip checks on longer agent tasks. One eval holding is evidence for one route.

Leading this

Reasoning changes the cost model under your team's feet, often without anyone choosing it. Current models think by default, defaults differ between models (Opus 5.5 runs at medium, Sonnet 5.5 at high), and a model upgrade can change effort behaviour. Ask four questions in design review. Is effort set explicitly for each route? Leaving it to the model's default means a model change silently changes your bill. Is max_tokens sized for thinking plus the answer? A cap sized only for the visible reply truncates hard cases, and you still pay for them. Are cost estimates built from measured output_tokens on real inputs? The visible answer length undercounts badly. Did anyone test a lower effort on the same model before reaching for a bigger model? That's lesson 6's question. And don't let anyone present the thinking summary as an audit trail. It's a summary written by a different model, of reasoning that was trained to earn a reward.

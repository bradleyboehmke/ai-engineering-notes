# Mission

## Why this exists

I'm a technical data scientist becoming a strong AI Engineer. I want to build
AI systems well myself, and I manage a team of Scientific Developers (ML, AI,
and optimization engineers), so I also need to scope, review, and lead this
kind of work.

This repo is where I plan what to learn, learn it, and publish what I learned
in a form other people can use.

## Objectives

1. Keep a clear, open-ended path for upskilling in AI Engineering. The path has
   no end; it extends as new concepts appear.
2. Make my learning efficient and organized.
3. Produce output others benefit from: a public website of topics, a linked
   dictionary of terms, prototypes, tools, and videos.

## Where I'm starting from

Strong already (do not teach me these):

- Machine learning theory and practice, including model evaluation
- Python and R, package development, testing, CI
- Teaching and technical writing; Quarto, GitHub Pages

Likely gaps (prioritize these):

- Building with LLM APIs: structured output, tool calling, streaming
- Context engineering and retrieval
- Agents: loops, tools, MCP, skills, sandboxing
- Production: services rather than packages, tracing, cost, security
- Leading AI engineering work: scoping, eval-driven planning, review standards

My edge: evaluation. Test sets, error analysis, and metric design transfer
directly to LLM evals, so I lean on evals early.

## Two lenses

I'm part practitioner, part leader, so every topic gets both angles:

- **Practitioner**: what this means for doing the engineering hands-on.
- **Leader**: what this means for scoping, reviewing, and leading AI engineers.

Each topic page closes with a short "Leading this" section. When the leader
angle has more to say, it gets its own leader page.

## Anchors

- **This repo's own tools.** Each stage's deliverable is a tool this repo
  needs (see `ROADMAP.md`).
- **A work project** (structured-data analytics agent over a semantic layer).
  It informs priorities and provides contrast with this repo, which is
  unstructured text. No work data or specifics go in this repo; anything
  public is rebuilt on open data.

## Rules I hold myself to

- **I draft first.** For topic pages and dictionary terms alike, I write the
  first draft. The agent then challenges my understanding (questions, gaps,
  misconceptions) and helps me edit toward clarity. It never writes the first
  draft, and agent-written notes don't count as learning.
- Do a task by hand a few times before building a tool for it.
- Install existing skills (`/teach`, `/grill-me`) before building my own.
- A stage is done when I've written its topic pages, not when I've read about it.
- Write first, record second: videos follow a written page.
- Links and my own words only. Never copy other people's content into the repo.
- No work data in this repo. Public prototypes use open data.
